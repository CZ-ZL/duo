# v0.6.3 — complete public delivery

This release provides a fixed plugin download and a complete public path from
installation through a saved report. Linux / Node 24+ and the declared
DSH 0.1.2-rc.1 / Cordis 4.0.2 composition define support. DSH itself remains an
upstream preview; trusted providers execute in-process.

## Changes

- Read-only `duo check-host` detects missing or unsupported host metadata before
  profile preparation. The shipped host manifest matches CI.
- English and Chinese Quickstarts focus on one free run. Model configuration,
  profile integration and troubleshooting have separate shipped guides.
- Provider contracts are organized by responsibility. Optional typed decisions
  and shadow judgment have dedicated pages.
- Private Controller helpers separate operation settlement, evaluation identity,
  development selection and independent final evaluation. Public tools and
  provider interfaces are unchanged. Existing checkpoint identity still changes
  with implementation bytes; re-plan instead of resuming across versions.
- Documentation file/anchor checks, exact historical exceptions, bilingual shell
  checks, script inventory and real Mermaid parsing run in the product gate.
- Simple is documented as a shared research baseline with compact diagrams and
  an English overview. Existing research results and frozen evidence are retained.

## Verification and limits

The Release's `VERIFICATION.json` identifies the delivered commit, successful
CI run, archive SHA-256 and installed-guide acceptance. The same archive checked
by CI is published; `SHA256SUMS` verifies the plugin download.

Offline verification checks product behavior, installation, recovery, accounting,
examples and supported host integration. It does not measure method efficacy.
The earlier [live starter](../../product-foundation/FIRST_USE.md) is reused for
unchanged model/evaluator behavior: both prompts scored 4/4 and the original was
retained. No new paid experiment is part of this release.

Start with [Quickstart](../../../dsh-plugin/QUICKSTART.md). Upgrades use a new
workspace and inspected plan. Preserve earlier archives and ledgers; a new
folder does not reset spending authority. See [QC](QC.md) for acceptance coverage.
