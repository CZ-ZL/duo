# DUO 0.5.0 Product Foundation acceptance

Status: local product acceptance and independent Caller PASS; private GitHub
CI/fresh dependency receipt pending. Method research is paused. Product measurements below do not prove
DUO quality or total-cost superiority. All local work-provider requests cost
CNY 0 and use no model API; the Agent review runs in the existing coding session.

## Product boundary

The lifecycle remains the existing native Controller. Target adapters now own
content identity and safe historical projection. Generator, Executor, Evaluators,
Comparator, Gate and Feedback/History remain Cordis service bindings. DSH supplies
model execution, dependency injection, lifecycle, ToolRuntime and permission.
No parallel registry, budget system or optimization runtime was introduced.

One capability catalog supplies describe/schema/current support. The default
bundle prepares and waits for work providers; it never silently measures a
research fixture. A small shipped CLI sets up isolated examples and transports
public tool calls through DSH. It contains no search or selection engine.

## Known limits

- Linux / Node 24 with tested DSH 0.1.2-rc.1 / Cordis 4.0.2. Windows/macOS and
  TypeScript semantic compilation are not qualified.
- Persona needs compatible work providers. Fetch config is partial: only
  maxBodyChars in the existing bounds; real fetch executor remains opt-in source
  research material. Custom adapters own their actual measurement correctness.
- The shipped example measures text hygiene, uses the same measurement at Fast
  and Slow and configures no independent final. A qualified recommendation is
  therefore insufficient_evidence even when development text changes. No
  higher-fidelity, generalization or method-effectiveness claim follows.
- Providers are trusted in-process code. Declared permissions do not isolate a
  malicious provider. DUO accounting covers inner operations, not every Caller
  request. Unknown receipts stop work; they are never treated as free.
- Recovery is limited to unchanged settled checkpoints within the original
  deadline. No arbitrary crash replay, automatic candidate adoption or npm
  registry publication. Historical plans must be re-inspected after upgrade.

## Retained failures and corrections

- Initial config warm/custom content reproductions failed before Target-owned
  history/identity hooks; original red and subsequent green receipts remain.
- First local CLI staging used a source symlink and failed dependency resolution;
  declared package-file staging corrected it.
- First replacement example used an id/name patch and left the old provider
  active. Disabling the old row and inserting a new provider corrected it.
- Native midpoint had one stale test invocation without its Target projector;
  final native suite passed after the invocation was corrected.
- Independent Caller noticed old Provider guide statements about default fixture
  and persona-only scope; those statements were corrected, old docs archived.
- Fresh registry install failed locally with TLS EOF. Offline tarball install
  passed against existing host peers; this is not fresh dependency validation.

No negative experiment, old Journal, candidate Delta, score, fee or consumed-final
status was rewritten. Historical documentation snapshots were checked byte-for-byte.
